# Sage — chat UI

A React front end for Sage, built on [assistant-ui](https://www.assistant-ui.com/).

The interesting thing about this directory is how little of it we wrote. Three files are ours; the
thread, composer, streaming render, markdown, auto-scroll, cancellation, and keyboard behaviour all
come from the library. Chat plumbing is not what Sage is for.

## Running it

Needs the API running alongside it:

```bash
# terminal 1 — the API, from the repo root
uv run poe dev

# terminal 2 — this
npm install
npm run dev          # http://localhost:5173
```

| Command | Does |
|---|---|
| `npm run dev` | Dev server, proxying `/chat` to the API |
| `npm run build` | Typecheck (`tsc -b`) then bundle |
| `npm run lint` | oxlint |

## The files we own

Everything under `src/components/` except `restart-notice.tsx` was generated by
`assistant-ui init` and is maintained upstream.

**[`src/lib/sage.ts`](src/lib/sage.ts)** — Sage's HTTP contract, and the only place that knows it.
Speaks `POST /chat/stream` and `GET /conversations/{id}`, parses the SSE frames, and yields a
`conversation` chunk followed by text. Above this file the app deals in turns and never in status
codes.

**[`src/lib/conversation-id.ts`](src/lib/conversation-id.ts)** — the id, in localStorage. The only
thing the client stores now.

**[`src/lib/sage-adapter.ts`](src/lib/sage-adapter.ts)** — a `ChatModelAdapter`, which is how a
question reaches Sage. assistant-ui messages carry an array of parts; Sage takes a string. The
flattening lives here so the API never has to learn a richer message shape than it needs.

**[`src/lib/server-history.ts`](src/lib/server-history.ts)** — a `ThreadHistoryAdapter`, which is how
the thread is recovered after a reload. It reads the id, fetches the turns from Sage, and forgets the
id on a 404.

[`App.tsx`](src/App.tsx) hands the first and last to `useLocalRuntime` and renders `<Thread />`. That
is the whole integration.

## Decisions worth reading

**The dev server proxies `/chat` to FastAPI.** The browser only ever talks to one origin, which is
not cosmetic: same-origin means no CORS on the API, no preflight, and no `credentials: 'include'` to
get wrong later. Sage stays a plain JSON service that curl can still drive. See
[`vite.config.ts`](vite.config.ts).

**The client stores an id and nothing else.** `append` on the history adapter is deliberately empty:
Sage wrote both halves of the exchange while it was answering, and a second write from here would be
the client asserting what was said — the exact thing moving storage server-side was meant to stop.

**Unreachable is not the same as gone.** A 404 from `/conversations/{id}` is a definite answer, so
the id is forgotten. A network failure is not, so the id is kept and a later reload finds the
conversation again. Collapsing the two would turn a brief API outage into permanent data loss.

**An expired conversation keeps its messages on screen.** When Sage reports `restarted`, the old
turns stay visible under a notice saying Sage no longer remembers them. Clearing them takes away
something the reader can still read; replaying them into the new conversation would mean the client
asserting history, which is the tampering server-side storage exists to prevent. So they stay, and
the notice explains why — otherwise the next few answers look like a bug.

**A mid-stream failure is not an HTTP error.** Sage sends `200`, then reports the failure as an
`error` event in the body, because by the time the model fails the status line is already sent. The
adapter treats that event as the failure it is rather than as content.

**A cancelled run stays a cancellation.** When the user stops a reply, `fetch` rejects — and that is
re-thrown untouched rather than wrapped, so the library sees an abort instead of an error to show.

## Not here yet

One conversation, not many — there is no thread list, and clearing the browser's storage loses the
id, which loses the chat. Anyone holding an id can read that conversation: there is no auth, so the
id is a bearer token and unguessability is all that protects it.
